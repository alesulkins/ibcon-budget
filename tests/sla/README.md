# Проверка нормативов времени отклика

Нормативы: страница и карточка проекта — 5 с, открытие версии
бюджета — 10 с, расчёт бюджета — 2 мин, выгрузка XLSX — 1 мин;
при десяти одновременно работающих пользователях.

Две проверки, разные по смыслу — нужны обе.

## 1. Нагрузка по API (`load_sla.py`)

Меряет сервер: десять потоков одновременно проходят цепочку
«реестр → карточка → версия → расчёт → выгрузка». Только стандартная
библиотека Python, ставить нечего.

```
python3 tests/sla/load_sla.py --users 10
python3 tests/sla/load_sla.py --url http://<стенд>:8080 --project 16 --version 23
```

Без `--project/--version` скрипт сам берёт первый проект, к которому у
учётки есть доступ и есть версия бюджета. Итог — таблица «p95 / макс /
норматив»; код возврата 1, если норматив превышен (годится для CI).

Проверка идёт мимо системного прокси: меряем приложение, а не
прокси-сервер рабочей станции.

## 2. Браузерная проверка (`sla.spec.ts`)

Меряет то, что видит пользователь: время до появления данных на экране,
а не ответ сервера. Chrome, Edge и Яндекс.Браузер, десять браузеров
одновременно.

```
npm i -D @playwright/test && npx playwright install chrome msedge
BASE_URL=http://localhost:5173 npx playwright test -c tests/sla/playwright.config.ts
```

Яндекс.Браузер Playwright не ставит — он не входит в набор
поддерживаемых каналов. Путь указывается вручную, движок тот же
Chromium:

```
YANDEX_PATH="/Applications/Yandex.app/Contents/MacOS/Yandex" npx playwright test -c tests/sla/playwright.config.ts
```

Без этой переменной набор для Яндекса пропускается, Chrome и Edge идут.

Учётка задаётся переменными `SLA_EMAIL` и `SLA_PASSWORD`. Пароля по
умолчанию нет: без него сценарии не запускаются. Число одновременных
браузеров — `USERS`, по умолчанию 10.
