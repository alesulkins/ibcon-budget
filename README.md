# IBCON Budget

Информационная система бюджетного планирования строительных проектов:
мастер ввода из 16 шагов, расчётное ядро, отчётность БДР/БДДС и выгрузка
в Excel. Замещает расчётную книгу из 20 листов, по которой планирование
велось вручную.

**Стек:** Go 1.26 · Gin · PostgreSQL · React 19 · TypeScript · antd v6 ·
excelize

---

## Аналитический модуль: оценка рыночной ставки аренды

Модуль решает задачу регрессии на разреженных и зашумлённых данных
объявлений: по параметрам объекта (город, район, число комнат, площадь)
оценивается ставка аренды, пригодная для закладки в бюджет проекта.

**Сбор данных.** Четыре независимых источника с индивидуальными
парсерами и собственной географией покрытия: Яндекс Недвижимость
(91 город), «Этажи» (12), N1.ru (14), House.kg (Киргизия — котировки в
сомах приводятся к рублям по курсу ЦБ РФ). Пагинация запрашивается
конкурентно, результаты дедуплицируются по кортежу признаков; ответ
кэшируется на 6 часов. Соответствие «город → адрес выдачи» верифицировано
поштучно: при неизвестном идентификаторе площадки подставляют
собственный опорный регион, что даёт систематическое смещение выборки
(запрос по Бишкеку возвращал московские котировки).

**Предобработка.** Стратифицированный отбор: точное совпадение по числу
комнат, окно по площади ±10 % с последовательным расширением до ±35 %
при недостаточном объёме выборки; фильтрация аномалий по правилу
1.5 × IQR отсекает как заведомо ошибочные объявления, так и посуточные
ставки, проставленные в поле месячной. Пропуски в признаках заполняются
средними обучающей выборки (impute by mean), исключая утечку статистик
на отложенную часть.

**Модели.** Выбор оценщика адаптивен к объёму выборки:

| Наблюдений | Оценщик | Гиперпараметры |
|---|---|---|
| < 40 | гребневая регрессия (Ridge) | λ = 1.0, свободный член без штрафа |
| 40–299 | случайный лес (Random Forest) | 60 деревьев, bootstrap, 3 признака из 4 на разбиение, глубина 8 |
| ≥ 300 | градиентный бустинг (GBDT) | 200 итераций, learning rate 0.05, глубина 3 |

Реализация собственная, на стандартной библиотеке Go: CART-деревья с
критерием уменьшения SSE и квантильным прореживанием порогов-кандидатов
(снимает квадратичную сложность построения), bootstrap-агрегация,
последовательное обучение на антиградиенте квадратичной функции потерь.
Качество измеряется MAE на отложенных 20 % выборки и публикуется вместе
с прогнозом; генератор псевдослучайных чисел детерминирован —
воспроизводимость результата на одинаковом запросе гарантирована.

**Итоговая оценка.** В бюджет закладывается усечённое среднее (trimmed
mean) по выборке, ограниченной 95-м перцентилем: отсечение верхнего
хвоста устраняет смещение среднего, сохраняя чувствительность ко всей
выборке, в отличие от медианы. Дополнительно публикуются 95-й перцентиль
как верхняя граница рынка, гистограмма распределения и репрезентативные
объявления. При отсутствии данных система возвращает явный отказ:
экстраполяция и подстановка значений по умолчанию не производятся.

Модуль: `backend/internal/market`

## Расчётное ядро

Двенадцать листов расчётной формы (ФОТ, премии, аренда жилья, транспорт,
обустройство стройплощадки, офис, ГПХ, субподряд, закупки) реализованы в
виде типизированных функций: перенесены сами формулы, а не итоговые
суммы. Реализованы индексация ФОТ, множители вахтовых графиков, расчёт
наценки через целевую рентабельность, банковские гарантии и поквартальный
налог на прибыль.

Корректность подтверждается golden-тестированием: эталонные значения
извлечены из заполненных расчётных книг, расхождений с формой не
зафиксировано. **225 тестов.**

Модуль: `backend/internal/calc`

## Управленческая отчётность

БДР и БДДС формируются из единого расчёта по плоскому кодификатору со
ссылками на строки формы; групповые агрегаты собираются по префиксу
кода. Различие БДДС — не в составе статей, а в моменте платежа: оплата
труда и НДФЛ распределяются двумя частями, страховые взносы смещаются на
месяц, налог на прибыль — на квартал. Выгрузка формирует книгу из трёх
листов (excelize); для роли администратора проекта состав выгрузки
ограничен накладными расходами.

Модули: `backend/internal/reports`, `backend/internal/budgets/export.go`

## Разграничение доступа

Матрица шести ролей и четырнадцати прав с возможностью выдачи
индивидуальных прав сверх роли. Авторизация выполняется на каждом
запросе совместно с идентификатором проекта: роль в отрыве от объекта не
определяет допустимость операции.

Модули: `backend/internal/access`, `backend/internal/auth/permissions.go`

## Защита периметра

Унифицированный ответ при неуспешной аутентификации (исключает
перечисление учётных записей), ограничение частоты попыток по IP и
адресу, список разрешённых источников CORS, обязательный JWT-секрет
длиной от 32 символов, автоматическое завершение сессии по неактивности.
Внешние CDN не используются: шрифты и статические ресурсы размещены
локально.

## Нагрузочное тестирование

`tests/sla` — сценарии Playwright и нагрузочный профиль на Python для
10+ одновременных пользователей. Контролируемые пороги: загрузка
страницы и карточки проекта ≤ 5 с, открытие версии бюджета ≤ 10 с,
расчёт ≤ 2 мин, формирование выгрузки ≤ 1 мин.

## Развёртывание

На сервере (наружу открыт только 80-й порт, база и API доступны лишь
внутри сети Compose):

```bash
cp .env.prod.example .env && $EDITOR .env      # пароль БД и JWT-секрет
docker compose -f docker-compose.prod.yml up -d
```

Требования: x86_64, 2 vCPU / 4 ГБ / 40 ГБ (рекомендуется 4 / 8 / 60),
Docker Engine 24+ и Compose v2. Схема БД накатывается миграциями при
старте контейнера.

Локально:

```bash
docker compose up                                             # всё разом
cd backend  && cp .env.example .env && go run ./cmd/server    # :8080
cd frontend && npm ci && npm run dev                          # :5173
```

## Тестирование

```bash
cd backend  && go test ./...             # ядро, права, отчётность, аналитика
cd frontend && npx tsc -b                # проверка типов
npm run sla:api && npm run sla:browser   # SLA под нагрузкой
```

## Структура

```
backend/internal/
  calc/       расчётное ядро листов формы
  market/     сбор данных и регрессионные модели оценки аренды
  reports/    БДР и БДДС
  budgets/    версии бюджета, выгрузка в Excel
  access/     авторизация в разрезе проекта
  auth/       аутентификация, роли, ограничение частоты
frontend/src/
  pages/budgets/   мастер ввода из 16 шагов
  pages/…          реестр, карточка проекта, справочники, личный кабинет
tests/sla/         нагрузочное тестирование
```

Эталонные расчётные книги и рабочие материалы разбора формул в состав
репозитория не входят как документы заказчика.
