# IBCON Budget

Платформа планирования бюджета строительных проектов: мастер из 16 шагов,
расчётное ядро, отчёты БДР/БДДС и выгрузка в Excel. Заменяет книгу из
20 листов Excel, по которой компания считала бюджеты вручную.

Go + Gin + PostgreSQL · React 19 + TypeScript + antd v6 · excelize

---

## Что здесь интересного

### Оценка рыночной стоимости аренды

Экономист вводит город, район, число комнат и площадь — платформа сама
собирает объявления и считает, сколько закладывать в бюджет.

* **Сбор данных.** Четыре площадки, у каждой свой парсер и свой список
  городов: Яндекс Недвижимость (91 город), «Этажи» (12), N1.ru (14),
  House.kg (Киргизия, цены в сомах пересчитываются по курсу ЦБ). Списки
  адресов выверены запросом по каждому: неизвестный город площадки молча
  подменяют своим главным, и запрос про Бишкек вернул бы Москву.
  Страницы выдачи запрашиваются параллельно, ответ кэшируется на 6 часов.
* **Отбор.** Комнаты сверяются точно, площадь с допуском ±10 % с
  расширением до ±35 %, если объявлений мало; выбросы отбрасываются по
  правилу полутора межквартильных размахов.
* **Модель.** Выбирается по размеру выборки: линейная регрессия с
  гребневой регуляризацией (<40 объявлений), случайный лес (40–299),
  градиентный бустинг (≥300). Всё написано на Go без внешних библиотек:
  CART-деревья с ограничением числа порогов, бутстрэп-агрегация,
  бустинг по остаткам. Пропуски заполняются средними обучающей выборки,
  ошибка меряется на отложенной пятой части.
* **Ответ.** Цена для бюджета — среднее по выборке, обрезанной 95-м
  перцентилем; рядом верх рынка, гистограмма распределения и примеры
  объявлений. Если площадки ничего не отдали, так и написано: оценка
  никогда не додумывается.

`backend/internal/market`

### Расчётное ядро

Двенадцать листов Excel-формы (ФОТ, премии, аренда жилья, транспорт,
стройплощадка, офис, ГПХ, субподряд, закупки) перенесены в Go — от
формулы к функции, а не «прокидыванием готовых сумм из формы».
Индексация ФОТ, множители графиков вахты, наценка через целевую
рентабельность, банковские гарантии, налог на прибыль поквартально.

Правильность держится golden-тестами: входные данные и ожидаемые числа
взяты из заполненных эталонных книг, расхождений с Excel нет.
**225 тестов.**

`backend/internal/calc`

### Отчёты и выгрузка

БДР и БДДС строятся из одного расчёта плоским кодификатором со ссылками
на строки формы; групповые суммы собираются по префиксу кода. Отличие
БДДС — не набор статей, а время платежа: зарплата и НДФЛ двумя частями,
взносы в следующем месяце, налог на прибыль на квартал позже. Выгрузка —
одна книга из трёх листов (excelize), у администратора проекта она
урезана до накладных расходов.

`backend/internal/reports`, `backend/internal/budgets/export.go`

### Права

Шесть ролей × четырнадцать прав, плюс индивидуальные права сверх роли.
Проверка идёт на каждом запросе вместе с идентификатором проекта — роль
без проекта не отвечает на вопрос «может ли он это здесь».

`backend/internal/access`, `backend/internal/auth/permissions.go`

### Безопасность

Единый ответ на неудачный вход (аккаунт не выдаёт себя ни отсутствием,
ни блокировкой), ограничение частоты по IP и почте, CORS по списку
доменов, обязательный JWT-секрет от 32 символов, автовыход по
неактивности.

### Нагрузочные проверки SLA

`tests/sla` — Playwright-сценарии и Python-нагрузка на 10+
одновременных пользователей с порогами: страница и карточка проекта
≤ 5 с, открытие версии бюджета ≤ 10 с, расчёт ≤ 2 мин, выгрузка ≤ 1 мин.

### Фронтенд

antd v6 в режиме CSS-переменных: тема, кегль и фирменный цвет — личные
настройки пользователя, хранятся в учётке и применяются мгновенно.
Автосохранение форм, перенос позиции прокрутки между версиями бюджета,
мобильная вёрстка мастера. Ни одного обращения к зарубежным CDN: шрифты
и все ресурсы локальные.

## Запуск

```bash
# всё разом
docker compose up

# или по отдельности
cd backend && cp .env.example .env && go run ./cmd/server   # :8080
cd frontend && npm ci && npm run dev                        # :5173
```

## Тесты

```bash
cd backend && go test ./...        # расчёты, права, отчёты, оценка аренды
cd frontend && npx tsc -b          # типы
npm run sla:api && npm run sla:browser   # SLA под нагрузкой
```

## Структура

```
backend/internal/
  calc/       расчётное ядро листов формы
  market/     оценка рыночной аренды: сбор данных и модели
  reports/    БДР и БДДС
  budgets/    версии бюджета, выгрузка в Excel
  access/     права на проект
  auth/       вход, роли, ограничение частоты
frontend/src/
  pages/budgets/   мастер из 16 шагов
  pages/…          реестр, карточка проекта, справочники, ЛК
tests/sla/         нагрузочные проверки
```

Эталонные книги Excel и рабочие разборы формул в репозиторий не входят:
это документы заказчика.
